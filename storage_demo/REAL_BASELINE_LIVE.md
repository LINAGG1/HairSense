# 실제 사용자 1명의 센서 baseline

이 경로는 두피 이미지 모델 분석과 별개입니다. 이미지 관련 모델·추론·결과 이력은 변경하지 않습니다.
기존 가상 데이터와 이미 저장된 실제 테스트 캡처는 새 baseline에 가져오지 않습니다.

## 설치 및 시작

1. 기존 서버를 중지하고 MySQL Workbench의 관리자 연결에서 `migration_real_baseline.sql`을 한 번 실행합니다.
   기본 DB는 `hairsense_demo`, 앱 계정은 `hairsense_app@localhost`입니다. 다르면 SQL에서 해당 이름을 맞춥니다.
   기존 테이블이나 데이터는 삭제하지 않습니다. 새 테이블이 없으면 신규 캡처 저장이 롤백되므로 먼저 설치해야 합니다.
2. 프로젝트 루트에서 서버를 시작합니다. 아래 ID는 예시이며 실제 사용할 사용자·기기 ID를 양쪽에 동일하게 지정합니다.

   ```powershell
   .\storage_demo\start_server.ps1 -DeviceId hairsense-001 -UserId user-001
   ```

3. 별도 터미널에서 대시보드를 실행합니다.

   ```powershell
   .\dashboard\start_dashboard.ps1 -DeviceId hairsense-001 -UserId user-001
   ```

서버와 대시보드의 `HAIRSENSE_REAL_USER_ID`, `HAIRSENSE_REAL_DEVICE_ID`가 같아야 합니다.
대시보드의 기존 이미지용 `SESSION_ID`, `BOOT_ID` 설정과 이미지 조회·분석은 그대로 유지합니다.
센서 결과는 해당 고정 세션 대신 실제 사용자·기기의 센서별 최신 결과를 조회합니다.
이미지가 없어 기존 이미지 화면이 열리지 않아도 센서 결과는 별도 영역에 표시됩니다.

## 한 측정의 의미와 학습 순서

- 기존 `/optical`(또는 광학 JSON을 받는 `/ai/analyze`) 및 `/gyro` 요청 1개가 완료된 측정 세션 1개입니다.
  개별 샘플 1개나 2초 구간 1개를 별도 측정으로 보지 않습니다. 기존 ESP32 업로드 형식은 바뀌지 않습니다.
- 광학과 자이로의 측정 이력·baseline·Isolation Forest·임계값은 서로 독립적입니다.
  서로 다른 센서의 최신 결과가 같은 측정 시각이라고 가정하지 않으며 화면에 각 세션과 저장 시각을 표시합니다.
- 처음 받은 유효 측정부터 시작합니다. 서버 적용 전에 이미 저장된 세션은 재전송하더라도 학습에 들어가지 않습니다.
  재부팅/새 캡처를 통해 기존 `(device_id, session_id, boot_id)`와 다른 키로 수집해야 합니다.
- 전처리는 기존 `analyze_real_sessions.features`를 사용합니다. 50 Hz, 2초당 100개 샘플,
  각 시간 슬롯에서 최대 5 ms 오차, 측정 채널 누락 없음 조건입니다.
  불완전·누락·시간이 불규칙한 구간은 보간 없이 제외하며, 나머지 유효 구간은 사용합니다.
- 광학은 평균·표준편차 2개, 자이로는 X/Y/Z별 평균·표준편차 6개를 추출합니다.
  기존 가상 데이터의 급변 임계값은 실제 사용자에게 적용하지 않습니다.
- baseline 생성에는 유효 구간 최소 2개(최소 4초)가 필요합니다. 부족하면 다음 측정까지 축적합니다.

| 일반 측정 | 비교에 쓰는 데이터 | 저장 후 다음 baseline |
| --- | --- | --- |
| 첫 번째 | 없음: 초기 baseline 생성 | 첫 번째 |
| 두 번째 | 첫 번째만 | 첫 번째 + 두 번째 |
| 세 번째 | 첫 번째 + 두 번째 | 첫 번째 + 두 번째 + 세 번째 |
| 네 번째 | 첫 번째 + 두 번째 + 세 번째 | 첫 번째부터 네 번째까지 |

결과를 계산·기록한 뒤 현재 특징을 학습 이력에 반영합니다. 원본, 비교 결과, 다음 baseline은 하나의 DB 거래로
확정하므로 부분 저장되지 않습니다. 같은 센서의 동시 업로드는 사용자·기기·센서 행 잠금으로 직렬화합니다.
순서는 서버가 완료된 캡처를 처리하는 순서이며, 기기 재부팅 후 초기화되는 timestamp로 전체 이력을 재정렬하지 않습니다.
재전송은 기존 결과를 반환하고 학습에 중복 반영하지 않습니다. 실패하면 전체 롤백 후 같은 요청을 재시도할 수 있습니다.

대시보드 조회는 학습을 실행하지 않습니다. 버튼을 누른 시점의 저장 결과를 보여주며, 이후 baseline이 갱신되어도
이미 저장된 과거 점수와 비교 baseline 버전은 바뀌지 않습니다. 새 결과는 다음 조회 때 표시합니다.

## 별도 기준 조정 세션

1. 각 센서의 첫 일반 측정으로 baseline을 생성합니다.
2. 대시보드의 **센서 기준 조정 세션**에서 센서를 선택합니다.
3. **기준 조정 → 다음 센서 측정에 적용**을 누른 뒤 평소 상태에서 별도 측정을 진행합니다.
4. 다음 유효 캡처 1개를 기준 조정 전용으로 저장하고 자동으로 일반 측정으로 돌아갑니다.
   유효 구간이 없는 캡처는 제외하며 기준 조정 예약은 유지합니다.
   예약을 취소하려면 **일반 측정 (기준 조정 취소)**를 선택해 적용합니다.

기준 조정 캡처는 Isolation Forest 학습이나 baseline 평균·표준편차에 포함하지 않습니다.
각 모델 갱신 때 보관된 기준 조정 특징을 새 모델로 다시 평가해 임계값을 다시 계산합니다.
여러 기준 조정 세션을 수집하면 모두 보관하고 임계값 결정에 사용합니다.

- Isolation Forest: 기존 `fit_sensor`를 재사용합니다. 트리 200개, `random_state=42`, `contamination=auto`.
- 이상치 점수: `-decision_function`. 기준 조정 점수의 상위 95% 분위수(`higher`)를 **초과**하면 표시합니다.
- 추가 규칙: 특징별 `abs(현재 특징 - baseline 평균) / baseline 표준편차` 중 최댓값을 사용합니다.
  0 또는 매우 작은 표준편차는 `max(abs(평균), 1) * 1e-6`으로 하한을 둡니다.
  같은 기준 조정 세션에서 규칙 점수의 95% 분위수를 정하며, 모델 또는 규칙 중 하나를 초과하면 해당 구간을 표시합니다.
- 별도 기준 조정 이전에도 두 번째 측정부터 비교할 수 있도록 학습 구간 자체로 **초기 임계값**을 계산합니다.
  화면과 저장 결과에 `provisional`로 명시합니다. 별도 기준 조정 후 `calibrated`가 됩니다.

요청한 누적 방식에 따라 이상치로 표시된 일반 측정도 비교 후 다음 학습에 포함합니다.
따라서 계속된 변화가 점차 baseline에 포함될 수 있습니다. 점수는 평소와의 상대적 차이이며 질환 확률이 아닙니다.
소량의 초기 개인 데이터나 기준 조정 데이터만으로 정확도를 보장하지 않습니다.

## 저장과 API

- `real_sensor_profiles`: 센서별 학습 특징, 기준 조정 특징, baseline 통계·임계값·버전, 다음 캡처 용도.
  모델 pickle 대신 특징과 고정 모델 설정을 저장합니다. 재시작 후 동일 특징으로 모델을 복원합니다.
- `real_sensor_events`: 변경하지 않는 비교 결과, 사용한 baseline, 구간별 점수, 전처리 품질.
- 기존 `sensor_readings`, `sensor_sessions`, `sensor_analysis_runs`도 기존 흐름대로 사용합니다.
- `GET /real-sensors/latest?user_id=...&device_id=...`: 센서별 최신 결과를 한 번의 DB 조회로 반환.
- `GET /real-sensors/baseline?user_id=...&device_id=...`: 다음 비교에 사용할 baseline과 기준 조정 예약 상태.
- `POST /real-sensors/{optical|gyro}/next-capture`: `{ "user_id": "...", "device_id": "...", "role": "calibration" }`.
  취소는 `role: "measurement"`.
- 특정 과거 결과는 기존 `/sensor-sessions/{session_id}/analysis` 경로로 조회합니다.

기존 가상 데이터 생성·분석 도구는 실험 재현용으로 남아 있지만 새 실제 센서 경로에서는 모델 파일을 로드하지 않습니다.
DB 결과가 authoritative하며 대시보드 새로고침이나 서버 재시작으로 학습 이력이 초기화되지 않습니다.

## 검증

`test_real_sensor_baseline.py`는 첫 번째부터 네 번째까지의 비교 순서, 현재 측정의 학습 누출 방지,
기준 조정 분리, 누락 구간, 사용자·기기 혼입 방지를 검사합니다.
`test_real_sensor_service.py`는 저장 실패 롤백, 재전송, 센서별 독립 이력, HTTP 입력 검증을 검사합니다.
`dashboard/test_real_sensor_ui.py`는 이미지가 없는 상태에서 결과 조회와 기준 조정 버튼을 검사합니다.

실제 MySQL 검증은 별도 생성한 식별자로 원본·학습·결과 저장을 실행한 뒤 **전체 롤백**합니다.
기존 사용자 데이터는 수정하지 않고 테스트 기록도 커밋하지 않습니다.

```powershell
cd storage_demo
$env:HAIRSENSE_TEST_MYSQL = '1'
..\.venv\Scripts\python.exe -m unittest test_real_sensor_mysql
```

이번 변경의 테스트는 실제 센서의 예측 정확도 검증이 아니라 데이터 처리·저장·화면 연결에 대한 검증입니다.
